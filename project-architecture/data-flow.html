End-to-End Data Journey

How sensor readings travel from the field through the network, get processed by the cloud intelligence engine, and trigger actuator responses — the full closed loop.

📡 Data Pipeline

Sensor → Cloud → Actuator Flow

Every measurement follows this path through the system in near-real-time.

🌱

Field Sensors (Perception Layer)

ESP32 samples soil moisture, EC, temperature, humidity, and liquid flow every 60s. Readings are timestamped and buffered locally.

ESP32 ADC
📶

Network Transmission

Data is published as a JSON payload via MQTT over TLS to the cloud broker. LoRaWAN is used for remote nodes beyond Wi-Fi range.

MQTT / LoRaWAN
☁️

Cloud Ingestion & Storage

Firebase Realtime DB persists telemetry. ThingsBoard aggregates time-series data and serves the dashboard API for the mobile app.

Firebase / TSDB
🧠

Central Coordination Engine

The State Machine evaluates all incoming sensor data against FAO-56 targets, GDD thresholds, and interlock conditions to compute the required action.

State Machine
📋

Command Dispatch

Actuator commands (irrigate / fertilize / spray / skip) are published back to the field via MQTT. The mobile app receives push alerts simultaneously.

MQTT Publish
⚙️

Actuator Execution (Perception Layer)

ESP32 receives the command and toggles solid-state relays to open/close irrigation valves, fertigation pumps, or spray nozzles. Flow meters confirm execution.

SSR / Relay
